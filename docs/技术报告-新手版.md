# 《实验史记·马刀行》技术报告（新手版）

> 写给第一次读这个项目的人。目标：读完这一篇，你知道这个项目用了什么技术、代码是怎么组织的、一个功能是怎么跑起来的，然后可以拿着 [新手阅读指南](新手阅读指南.md) 开始逐文件啃代码。
> 另有一份面向开发过程的《技术报告.md》在仓库根目录，记录设计决策与平衡采样，两份互补。

---

## 1. 这个项目是什么

一个**双击就能玩**的校园开放世界网页游戏：外面一层是自由行走的校园箱庭（接任务、逛场景、加好感），走进「令」标记就切进一层 7×7 格子的回合制战棋战斗。两套玩法分别来自前作《实验史记·春秋笔》（世界壳）和《实验史记·马刀风云》（战斗内核），本项目把它们缝在一起，并新增了任务系统、刀谱成长、难度自选等融合层玩法。

## 2. 技术栈

| 项 | 用了什么 | 说明 |
|---|---|---|
| 语言 | 原生 JavaScript (ES6+) | **没有任何框架**（没有 React/Vue，没有 npm 依赖） |
| 画面 | HTML5 Canvas 2D | 校园世界和小游戏直接在 `<canvas>` 上逐帧画 |
| 战斗画面 | DOM + CSS | 战棋用 HTML 元素摆格子，配合 CSS 动画 |
| 音效 | WebAudio API | 全部音效用代码现场合成，**项目里没有一个音频文件** |
| 存档 | localStorage | 世界档 `shiji_cqb_v1`，战斗档 `shiji_madao_v1` |
| 模块系统 | 无 | 23 个 `<script>` 标签按依赖顺序加载，靠顶层全局变量通信（见 §4，这是全项目最需要理解的约定） |
| 打包 | Python 脚本 `build.py` | 把 23 个 JS + CSS 内联进一个 HTML，生成零网络请求的单文件版 |
| 测试 | Node 内置 + Playwright | 引擎层纯 Node 直测；界面链路用 Playwright 驱动真浏览器跑断言 |
| 文档工具 | md2docx.cjs / export_pdf.py | 技术报告 markdown → Word → PDF（与游戏本体无关） |

**零依赖**是刻意的设计目标：不装任何东西、不发任何网络请求，`file://` 协议双击即玩，也因此永远不会因为 CDN 挂了/版本升级而坏掉。代价是没有模块系统和类型检查，靠约定和测试纪律兜底。

## 3. 总体架构：四层

```
┌─────────────────────────────────────────────────────────┐
│  index.html  （DOM 骨架 + 按依赖顺序加载 23 个 script）      │
├─────────────────────────────────────────────────────────┤
│  世界层（春秋笔校园）                                       │
│    config.js   工具箱：选择器/数学/弹簧动画/音效/存档         │
│    engine.js   世界状态机：章节/进度/事件/风险/成就           │
│    world.js    Canvas 校园：寻路/NPC/相机/输入/主循环        │
│    dialog.js   对话播放器    writing.js 撰史支线             │
│    ui.js       世界侧面板    minigames.js 小游戏            │
│    data/       people(人) scenes(场景) events(事件)         │
│               volumes(卷) items(道具) —— 纯数据表           │
├─────────────────────────────────────────────────────────┤
│  融合层（本项目新增，把两套玩法缝起来的线）                    │
│    quests.js    任务系统：难度表/主线9节/支线7条/指引卡        │
│    blades.js    刀谱成长：录技/身怀之技/稀有刀卡/养成模式      │
│    duels.js     战斗胶水：约战/结算钩子/锦标赛/试炼/生存       │
│    battle-ui.js 战斗覆盖层（正式生效的战斗界面）              │
│    main.js      世界流程总指挥：开局/日常交互/任务入口/终章    │
├─────────────────────────────────────────────────────────┤
│  战斗层（马刀风云整体移植，可独立测试）                       │
│    battle/config.js  规则常量/难度/AI 档位                  │
│    battle/data.js    33 张角色战斗卡 + 增益池（数据）        │
│    battle/engine.js  战棋引擎（不碰 DOM，Node 可直测）★核心  │
│    battle/audio.js   battle/save.js   battle/scenes.js     │
├─────────────────────────────────────────────────────────┤
│  遗留参考件（index.html 不加载，别在这里找逻辑！）             │
│    battle/ui.js、battle/main.js（原版《马刀风云》单文件版）   │
└─────────────────────────────────────────────────────────┘
```

分层的意义：**战斗引擎不知道世界的存在**（它只收到一个配置对象 `cfg`，算完把结果交给回调），世界层也不知道战斗内部怎么算（它只调 `SJI_UI.startBattle(cfg)` 然后等结果）。所以引擎能在 Node 里单独跑测试，两边改互不牵连。

## 4. 最关键的约定：没有模块系统时，文件怎么协作

浏览器按 `<script>` 标签出现顺序执行代码，先加载的文件的全局变量，后加载的文件都能看见。本项目就靠这一点通信：

- 每个文件顶层写 `const Engine = {...}`、`const World = (() => {...})()`，这个 `Engine`/`World` 就成了**全局变量**，别的文件直接用裸名访问。
- 加载顺序 = 依赖顺序：`config.js`（工具箱）最先，`data/` 数据表其次，然后是各层逻辑，`main.js`（总指挥，谁都依赖）**必须最后**。顺序在 index.html 末尾，动了就白屏。
- **大坑（全项目踩过 5+ 次）**：顶层 `const` 声明**不会**挂到 `window` 对象上（`var` 和显式赋值才会）。所以 `window.Engine` 是 `undefined`，代码里到处用 `typeof Engine !== 'undefined'` 判活 + 裸名访问，**不要写 `window.Engine`**。例外：世界状态对象 `G` 因为开局要整体重建，是显式 `window.G = {...}` 挂的。
- 命名空间隔离：战斗层的全局一律 `window.SJI_*` 前缀（`SJI_CONFIG`/`SJI_DATA`/`SJI_ENGINE`/`SJI_AUDIO`/`SJI_SAVE`/`SJI_UI`/`SJI_BATTLE_HOOKS`/`SJI_DEBUG`），和世界层的裸名全局（`Engine`/`World`/`Quests`/`Blades`/`Duels`/`Dialog`/`UI`/`Main`）井水不犯河水（`Duels` 和 `G` 一样是少数显式挂 `window` 的）。
- 输入隔离：`window.BATTLE_ACTIVE = true` 期间，世界层的键盘/指针处理让位给战斗层——两个"游戏"叠在一张页面上，靠这个开关决定谁听输入。

## 5. 一场战斗的完整旅程（最重要的数据流）

理解了这条链，项目就读懂了一半：

```
玩家走近「令」标记
  → world.js 画出任务气泡，main.js 弹出交互条
  → Main.onQuest(quest)：播战前剧情 pre（dialog.js）
  → Quests.pickAndStart / Duels.challenge（js/duels.js 战斗胶水）：
    组战斗配置 cfg（难度 DIFFS + 敌方阵容 + cfg.stage 战场参数）
  → SJI_UI.startBattle(cfg)（battle-ui.js）：点亮战斗覆盖层，window.BATTLE_ACTIVE = true
  → SJI_ENGINE 开打：猜拳 → 行动 → 敌方 AI → …… → 分出胜负
  → SJI_BATTLE_HOOKS.onResult(b)（duels.js 注册的钩子被引擎回调）
  → 战胜：Blades 录技（把这人的招式记进刀谱）、Quests.complete 挂起战后剧情
  → onDone() 回世界：BATTLE_ACTIVE = false，先弹章节里程碑卡（Engine.takePendingChapter），
     再播战后一幕（Quests.takePendingPost）——两者成对消费，不串场
```

世界侧和战斗侧全程只通过 `cfg`（下行）和两个钩子（上行）说话，这就是 §3 说的"引擎不动世界"。

## 6. 数据驱动：改内容 = 改数据文件

机制代码和内容数据是分离的，改内容不用动逻辑：

| 想改什么 | 改哪个文件 |
|---|---|
| 主线/支线任务、难度数值 | `js/quests.js`（DIFFS/MAIN/SIDE 表） |
| 人物对话、好感、位置 | `js/data/people.js` + `js/battle/data.js`（同名 id 的战斗卡） |
| 校园名场面事件 | `js/data/events.js` |
| 场景地图、传送点 | `js/data/scenes.js` |
| 敌人强度、技能数值 | `js/battle/data.js` |
| 新的战场规则（特则） | `js/battle/engine.js`（按触发时机散布，搜 `this.rule` 集齐）+ `js/duels.js` 的 TRIALS 表引用 |
| 约战/试炼/锦标赛的敌人与地形 | `js/duels.js`（DUEL_SPECIAL / TRIALS / startTournament） |
| 界面文案 | 对应功能所在 js 文件（文案多内联在逻辑里） |

## 7. 测试体系（三层漏斗）

1. **引擎单元测试**（最快，纯 Node 无浏览器）：`node tests/battle/engine/` 下 18 个 `test_*.mjs`（另有胜率/压测等 3 个模拟脚本），覆盖规则/特则/被动继承/平衡/边界 bug。因为引擎不碰 DOM，才能这么测。
2. **剧情链路测试** `node tests/quest_flow.mjs`：Playwright 开真浏览器，走"选难度→打主线→解锁支线→结算"整条任务链。
3. **全链路冒烟** `node smoke.mjs`：Playwright 几十项断言 + 验收截图存 `testshots/`；`python build.py` 打包后对单文件版再跑一遍，保证"打包版没打包坏"。

另有效率工具：`tests/battle/engine/mainquest_winrate.mjs` 用机器人（kiteBot）自对弈采样主线 9 节 × 各难度档位（`DIFFS` 共 5 档：easy/normal/hard/extreme/nightmare）的胜率，做数值平衡。教训记录：greedyBot 对高倍率近战角色必 0 分，不能当唯一平衡依据。

## 10. 已知坑清单（前人踩过的）

1. **`const` 全局不挂 `window`**：跨文件访问用裸名 + `typeof X !== 'undefined'`，别写 `window.X`（见 §4）。
2. **战场参数必须放 `cfg.stage`**：`hpScale`/`restFull`/`blocked`/`terrain` 引擎只从 `cfg.stage` 读；曾写在 `cfg` 顶层导致 11 处血量缩放**静默失效**（不报错、只是没生效——最阴险的一类 bug）。
3. **测试别用固定 sleep 等动画**：一律 waitFor 轮询状态；动画时长是魔数，睡 700ms 时好时坏。
4. **断言要"必须含/不得含"**：`textContent.length > 0` 会被兜底文案（如"未入册"）蒙混过关。
5. **判面板是否开着**要看 `#panel` 的 `hidden` 类，别只看标题文本（标题关面板后不清空）。
6. **动画回调要兜底**：挂在弹簧动画上的收尾回调必须幂等 + 超时兜底，不能赌动画一定跑完（曾致对话卡死）。
